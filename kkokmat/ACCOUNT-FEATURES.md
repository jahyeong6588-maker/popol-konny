# 꼭맞 계정 저장 기능

공개 사이트에서 비회원 비교를 유지하면서 카카오·네이버 로그인을 선택적으로 사용한다. 로컬에서는 등록된 개발자 앱으로 카카오·네이버 로그인을 검증했다. 앱 등록과 비밀 설정은 SOCIAL-LOGIN-SETUP.md를 따르며 실제 키는 소스에 포함하지 않는다. ChatGPT 로그인 UI와 플랫폼 식별자 기반 계정 인증은 제거했다.

로그인한 사용자는 자녀를 여러 명 등록할 수 있다(최대 20명). 자녀마다 이름/별명, 선택 키·체중과 측정일, 입던 옷장 50개, 저장한 비교 100개, 최근 비교 기록 100개를 별도로 보관한다. 가입 전 비교는 그대로 가능하고, 결과의 저장 버튼에서 계정 저장/브라우저 저장 중 선택한다. 로그인 이전의 비교 입력과 저장 요청은 현재 탭에 잠시 보관하고 돌아오면 이어간다. 기존 브라우저 저장은 사용자가 복사 버튼을 누를 때만 계정으로 가져온다.

로컬 UI 주석 반영: 선택 성별과 프로필 사진을 추가했다. 성별은 프로필 표시용이고 추천 계산에 사용하지 않는다. 사진은 브라우저에서 정사각형 JPEG로 줄인 후 최대 48,000자 데이터 URL로 계정 소유자의 프로필에 저장한다. 기존 프로필에는 새 SQL 마이그레이션으로 nullable 필드만 추가한다. 기본 이미지는 직접 포함한 중립적인 일러스트다. 공식 브랜드 로고 12개와 실측 실내복 사진 158개를 캐시하며 원본 출처는 `public/assets/media-sources.json`에 기록한다. 결과 정렬은 추천순·이름순·신상품순을 제공하되 공식 출시일이 미공개인 상품은 날짜를 추정하지 않고 추천순을 유지한다.

첫 화면은 아이 프로필이 없으면 기존 일반 히어로와 비교 입력 화면을 유지한다. 로그인만 되어 있어도 아이 등록을 먼저 요구하거나 비교를 자동으로 계정에 기록하지 않는다. 비교 결과 하단의 “아이 정보 입력하고 저장하기”를 선택하면 필요한 로그인과 아이 정보 입력을 거쳐 방금 확인한 비교 결과를 계정에 저장한다. 등록을 완료한 사용자는 아이 이름이 들어간 개인화 홈과 자동 비교 기록을 이용한다. 편안하게 맞는 옷을 저장했다면 그 옷으로 비교를 시작하는 버튼을 보여준다. 작아졌거나 여유가 많은 옷은 옷장에서 착용감을 변경할 수 있다.

## 코드와 실행

- `public/`: 공통 비교 앱과 정적 데이터, `account.js`, `account.css`
- `responsive-app.js`는 모든 폭에서 `mobile-app.js`를 로드한다. 화면 폭 변경으로 앱을 다시 불러오지 않으므로 진행 중인 비교를 유지한다.
- `mobile-design.css`와 기존 모바일 CSS 선언을 공통 기준으로 사용한다. 모바일의 색·서체·그림·문구는 유지하고, `desktop-layout.css`에서 721px 이상 상단 메뉴와 결과 2단 배치, 960px 이상 히어로/입력 폼 2단 배치만 적용한다. 기존 `app.js`는 보관하지만 로드하지 않는다.
- `worker/index.js`: 소셜 로그인 서명 세션에 따른 소유자별 D1 API. 쓰기 요청의 출처, 크기, 입력값을 검증한다.
- `db/schema.ts`, `drizzle/`: 생성된 스키마와 순차 적용하는 SQL 마이그레이션
- `npm test`: 기존 비교 규칙 및 계정 접근 제한·저장 검증
- `npm run db:generate`: 스키마 변경 후 SQL 생성
- `npm run build`: `dist/client`, `dist/server`, 배포 메타데이터 생성. Windows에서는 미리보기 서버를 먼저 종료한다.
- `npm start`: Wrangler 로컬 Worker/D1 미리보기(4178)
- `node scripts/local-account-preview.mjs`: 인증을 우회하지 않는 루프백 전용 프록시(4180). 인증 처리는 Worker가 담당한다.

첫 로컬 실행에는 빌드 후 `node node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_dark_the_hand.sql`로 SQL을 한 번 적용한다. 프로덕션 DB는 Sites 배포가 마이그레이션을 적용한다.

배포 주소와 공개 범위는 기존 Site를 유지한다. 개인 저장 데이터는 API에서 전달되는 서명된 소셜 계정 식별자로만 조회하며 클라이언트가 소유자를 선택할 수 없다. 예시 아이 정보는 로컬 검증 DB에만 입력한다.

## 여러 자녀와 프로필 메뉴 (2026-11-19, 로컬 반영)

상단 프로필 버튼에서 현재 자녀 선택, 아이 정보 수정, 자녀 추가, 내 아이·옷장 이동, 로그아웃을 제공한다. 첫 등록은 “아이 정보 저장하기”로 한 명만 마치거나, “저장하고 다른 자녀 추가”로 다음 빈 폼을 이어서 연다. 등록한 자녀 수는 자동으로 표시되며 내 아이 화면의 자녀 버튼에서도 전환할 수 있다.

`children`과 `account_settings` 테이블을 추가하고 옷장·비교에 `child_id`를 연결했다. 기존 단일 프로필은 해당 계정의 첫 조회에서 멱등 DML로 첫 자녀에 연결한다. 사진·이름·키·체중·측정일과 기존 기록 ID/내용을 보존하며, 다른 계정의 자료는 처리하지 않는다. 마이그레이션 `0002_cooing_vargas.sql`은 스키마만 변경한다. 요청 시 DDL은 실행하지 않는다.

선택한 자녀는 서버에 저장하고 각 요청은 `X-Child-Id`로 화면의 자녀를 명시한다. 서버는 모든 조회·수정·저장에서 로그인 계정의 소유권을 확인한다. 전환 시 이전 자녀의 진행 중인 비교 입력/결과는 초기화한다. 자녀별 옷장과 저장한 비교는 섞이지 않는다.

로컬 D1은 `.wrangler/cta-state`를 사용하며 변경 전 일관된 SQLite 백업은 Git 제외된 `.artifacts/`에 보관했다. 공개 사이트와 공개 DB에는 적용하지 않았다. 테스트용 자녀만 정리하고 기존 프로필 사진/입력값 및 기록 건수 보존을 확인했다.

2026-11-19 UI 주석 반영: 진행 단계 막대와 개인화 홈의 “다른 옷으로 비교하기”를 제거했다. “저장한 옷으로 비교하기”는 선택한 자녀의 옷장 목록 팝업을 열며, 명시적으로 고른 옷의 종류·상품·사이즈·착용감을 기준 입력에 적용한다. 상품 목록의 사이즈는 독립 버튼으로 제공하고 드롭다운과 양방향으로 동기화한다. 실측이 부족한 사이즈는 선택을 비활성화한다. 로컬에서 팝업 선택, 80→110 변경, 다음 화면의 기준 요약 전달을 확인했고 전체 테스트 81개가 통과했다. 배포 및 사용자 저장 데이터 변경은 하지 않았다.

2026-11-19 Figma @디자인(54:1653, 화면 54:1654) 반영: 비회원 첫 화면에 손글씨 제목, 원본 우표 일러스트와 별 장식, 새 소개 문구를 적용했다. “꼭맞이 찾는법”은 기존 비교 기준 안내를 열고, 로그인 버튼은 사용자 요청대로 기존 디자인/기능을 유지한다. 입력 탭은 양쪽 동일 폭으로 정렬하고 착용감 안내 배경과 모바일 폼 간격을 맞췄다. 기존 자녀별 개인화 홈·저장 흐름과 상품 데이터는 유지한다. 화면 밖 작업용 요소와 캡처 당시 중간에 고정된 내비게이션 위치는 가져오지 않았다.

2026-11-19 로그인 홈에도 새 Figma 히어로를 적용했다. `home-hero.js`가 비회원/개인화 히어로의 원본 일러스트·별 장식·안내 버튼을 공유한다. 아이 이름과 저장한 옷 선택/등록 버튼은 동적으로 유지한다. 개인화 제목은 “아이이름에게,” / “다음옷을 찾아볼까요?” 두 줄로 표시하며 320px·390px 콘텐츠 폭에서 확인했다. 실제 로그인 상태에서 옷장 팝업과 저장한 옷 선택 후 비교 대상 화면으로 바로 이동하는 흐름을 검증했다. 사용자 프로필과 저장 자료는 수정하지 않았으며 로컬에만 반영했다.
